# macOS 实现代码审查记录

日期：2026-11-09。范围：React 控制面板、Rust 音频服务、Core Audio 原生桥接、Tauri 权限及退出流程。

采用 adp-code-review-skills 的资源、并发、边界、错误和安全检查项；本项目没有数据库、租户或 RPC，相关服务端检查不适用。

## 已修复问题

- 退出时原声恢复与设备枚举耦合：新增独立 shutdown 操作，清理成功即可结束，不依赖设备仍然存在。
- 恢复原声失败时可能再次自动应用规则：恢复流程先暂停规则恢复；shutdown 期间拒绝后续命令，成功后停止后端工作线程。
- 旧输出格式和旧进程继续使用既有 tap：快照和操作入口检查默认设备、采样率、进程集合及回调进展，异常时清理或重建。
- 部分声道写入失败造成设备状态不一致：音量写入失败尝试恢复原各声道值，并报告操作错误。
- FFI 只能拦截 C++ 异常：补充 Objective-C 异常保护；回调对象在停止失败时保留，避免释放仍在使用的内存。
- 拖动滑块切换设备后发送错误目标：设备滑块按稳定设备 ID 重建，独立队列串行、合并操作；卸载后取消待发送参数。
- 事件订阅第二次注册失败时泄漏首个监听：部分注册失败时清理；快照用宿主实例及 revision 过滤旧事件。
- 高频命令可饿死设备轮询并频繁写配置：有界命令队列、独立轮询时限、配置 400 ms 防抖及退出刷新。
- 原生接受数字静音值而 Rust 保存要求 bool：Rust 在执行前统一验证类型、目标标识、命令白名单与范围。
- 多个 helper 显示为辅助应用：优先从可确认的外层 app bundle 识别归属；无法确定 WebKit 所属时明确禁用，避免错误归并。

## 资源与安全检查

- 实时回调仅处理缓冲、增益与 lock-free 原子计数；不访问 Tauri、文件、JSON 或阻塞锁。
- HAL 创建的 tap/aggregate/IOProc 全程持有明确的 owner，失败路径清理；停止失败不能释放回调上下文。
- FFI JSON 使用原生分配/原生释放，Rust 复制后释放；平台对象只由后端工作线程访问。
- WebView 仅加载本地前端。command manifest 明确限制 mixer 窗口访问，前端无任意 shell 或文件写入接口。
- 输入权限与设备增益控制分开；aggregate 排除麦克风输入。信号测量仅保存每次回调 RMS 数值。
- diagnostic 模式需要明确命令行参数，正常启动不执行测试音频或自动降低系统设备音量。

## 验证边界

代码审查未发现需要阻断本轮测试的已知致命问题。回放听感、设备驱动崩溃行为、蓝牙重连、权限撤销和全设备兼容性需要真机测试，不能由静态审查证明。

该实现仍属于开发版本。尚未签名公证，不声称完成产品文档全部验收。具体测试结果记录在 macOS 实现进度文档中。
