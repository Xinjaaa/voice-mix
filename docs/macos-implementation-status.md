# macOS 实现与验证结果

日期：2026-11-09。状态：可构建的 macOS 开发版本；Windows/Linux 后端尚未实现。

## 实现范围

React 提供输入/输出设备和应用音量面板、设置页、完整设备管理和规则重置。Rust 服务串行管理音频命令、验证参数、发布版本化快照、保存规则，并在退出时停止规则应用、清理音频和结束工作线程。

Objective-C++ 通过 C ABI 接入 Core Audio。设备控制包含能力探测、主音量或声道音量、静音、默认设备选择及回读。应用控制使用 Process Tap 和私有 aggregate device，回调完成增益平滑和回放；仅适配默认设备双声道 float32 路径。

当前使用 400 ms 定时轮询同步设备和应用状态，后续可改为系统监听触发并保留低频恢复轮询。规则采用 400 ms 防抖保存，正常退出刷新。主动停止、格式/设备/进程变化或异常时恢复原声；变更后的链路提供手动重试，不反复启动失败资源。

## 已验证

环境：Apple Silicon、macOS 26.6.2、Xcode 26.5、Rust 1.92、Node 22。

| 检查 | 结果与范围 |
| --- | --- |
| TypeScript 与前端生产构建 | 通过 |
| Rust tests | 3 项通过：参数、规则配置、文件替换 |
| Rust format / Clippy | 通过，Clippy 使用 `-D warnings` |
| 前端 tests | 5 项通过：滑块合并/取消、键盘最终值、旧快照/旧宿主过滤 |
| 原生回调测试 | 通过：25%/50% 增益、静音为零、独立会话、planar/bounds 和缺失输入清零 |
| 真机设备枚举 | 识别 USB Z1 输入/输出、内置麦克风/扬声器、外接显示器 |
| 设备实际写入与回读 | 默认 USB 输入/输出已短暂写入并恢复原值；读取到硬件量化值 |
| 实际包内 Process Tap | 测试播放器 afplay 成功建立 tap、aggregate、IO，回调持续运行 |
| 实际回调信号 RMS | 25% 比例 0.25，静音比例 0，50% 比例 0.5；恢复清理返回成功 |
| 浏览器 UI | 启用、静音、规则重置交互通过，控制台没有运行错误 |

RMS 在回调内对 tap 输入和已填写的输出缓冲测量，未录制音频。该测试确认数据处理与回调运行，不等同于测量物理设备的最终声压，也未独立证明原始声完全没有叠加。

已构建 Apple Silicon 的 debug 与 release `.app` / `.dmg`；release DMG 约 3.1 MB，磁盘映像校验通过。release 构建使用本地签名配置，不等同于 Developer ID 正式分发。

## 限制与待完成验收

- 尚未完成所有浏览器辅助进程归属；不确定 WebKit 进程显示禁用原因。
- 多应用真实播放隔离、系统权限撤销/拒绝、睡眠唤醒、蓝牙/AirPlay 和长时间播放未完整验收。
- 强制终止后的 HAL 清理尚需验证，当前不能承诺故障后必然无声或恢复原声。
- 内置/有线输出额外延迟、CPU/内存目标和物理回放听感尚未测量。
- 面板改为启动时隐藏、无标题栏，点击菜单栏图标时按所在显示器定位，在图标下方居中并限制于可用区域；较小屏幕缩短面板高度。已增加位置计算测试，支持失焦、再次点击托盘、关闭按钮及 Esc 收起；混合缩放多屏、Space/全屏和托盘点击与失焦事件顺序仍需真机验收。
- 配置损坏或读取失败时不覆盖原文件，本次规则仅在内存中生效，并显示原因。
- 分发未配置 Developer ID 签名、公证和自动更新。macOS 14.4 与 Intel 尚未真机验收。

## 与设计文档的实现差异

为尽快验证原型，平台后端与服务暂集中在 `src-tauri/src/backend.rs`，通过单个受 ACL 限制的 `audio_request` command 分派白名单操作；后续规模扩大再拆分 crate 和类型化 DTO。

首次启动不自动捕获音频，用户启用混音后恢复规则。监测到设备/进程变化时先恢复原声，由用户重新应用规则。高级路由、增益超过 100%、EQ、场景预设不属于当前实现。
